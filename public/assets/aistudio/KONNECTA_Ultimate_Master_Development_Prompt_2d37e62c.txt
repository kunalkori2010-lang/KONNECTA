10. SECURITY AND PRIVACY ARCHITECTURE

Treat security as a fundamental engineering requirement.

AUTHENTICATION: - Established authentication provider. - Secure password
handling. - Session expiration. - Session revocation. - Optional MFA. -
Login rate limiting.

DATABASE: - PostgreSQL. - Row Level Security. - Server-side
authorization. - Strict group membership verification. - Secure
migrations. - Database constraints. - Auditable access policies.

END-TO-END ENCRYPTION:

For private and group messaging: - Use an established, maintained and
independently reviewed E2EE protocol implementation. - Never invent
cryptographic algorithms. - Keep private keys under user-device
control. - Use appropriate device identity and key management. - Support
secure device addition and removal. - Rotate group keys when membership
changes. - Prevent unauthorized future message access. - Avoid plaintext
server-side message logs.

Clearly document which metadata remains visible to the service.

Do not claim WhatsApp-equivalent encryption without independent security
verification.

IMPORTANT E2EE COMPATIBILITY RULE:

Server-side plaintext search, AI summarization, content moderation and
message indexing cannot simply operate on ciphertext.

Implement these features using client-side processing, explicit
user-authorized processing or separate unencrypted content where
appropriate.

Clearly explain limitations.

FILE STORAGE:

-   Private storage buckets.
-   Encryption at rest.
-   HTTPS/TLS.
-   Per-file authorization.
-   Short-lived signed URLs.
-   File type validation.
-   File size restrictions.
-   Malware scanning.
-   Upload quotas.
-   Safe downloads.
-   Secure deletion workflows.

For files requiring end-to-end confidentiality, encrypt on the client
before uploading and manage decryption keys separately.

Do not confuse server-side storage encryption with E2EE.

APPLICATION SECURITY:

-   Input validation.
-   Output encoding.
-   XSS protection.
-   CSRF protection where applicable.
-   SQL injection prevention.
-   Rate limiting.
-   Secure HTTP headers.
-   API authorization.
-   Secret management.
-   Dependency scanning.
-   Audit logging.
-   Encrypted backups.
-   Recovery testing.

Never expose service-role keys or encryption secrets in client-side
code.
